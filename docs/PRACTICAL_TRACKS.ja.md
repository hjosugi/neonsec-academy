# CEH+ 実践トラック

CEH の先を見据え、次の実践トラックを用意する。

## トラック 1: ペンテストエンゲージメントワークフロー

ワークスペース: `/tracks/pentest` は架空のエンゲージメント（Neon Harbor Logistics）を 5 ステップで進めます —
スコープ違反クイズ付きのスコープレビュー、交戦規定（RoE）の確認、書面スコープに基づく資産インベントリ、準備済み
スキャナー/手動テストメモのトリアージ（確認済み・誤検知・スコープ外と重大度）、レポート提出。各ステップに
チェックリストと成果物があり、最終成果物は確認済み所見から生成する Markdown レポートで、Report Builder でも開けます。

焦点: スコープ、エンゲージメントのルール、証拠、発見のトリアージ、報告。

セーフモード: 合成組織と静的データセットのみ。

## トラック 2: アプリケーションセキュリティコードレビュー

ワークスペース: `/tracks/appsec` には 10 個のコードレビューチャレンジ（`src/data/tracks/appsec.ts`）があり、
認可、入力検証、シークレット管理、エラー処理、依存関係リスクを各 2 問ずつ、TypeScript・JavaScript・Python・
Java・Go・マニフェストのスニペットで扱います。学習者は脆弱な行を選び、脆弱性を分類し、影響と修正を書きます。
結果には解説、安全な修正例、ユニットテストのアイデアが表示され、トリアージ所見やレポート所見にできます。

焦点: 認可、入力検証、秘密情報の取り扱い、依存関係リスク、セキュアな修正。

セーフモード: おもちゃのコードスニペットのみ。

## トラック 3: クラウド IAM / 設定レビュー

ワークスペース: `/tracks/cloud` にはベンダー中立の設定レビューチャレンジが 8 個（`src/data/tracks/cloud.ts`）あり、
IAM の過剰権限、公開露出、弱いログ、暗号化の欠如、シークレット管理を架空のアカウント ID のみで扱います。
学習者は危険な行を選び、リスクを分類し、リスクと修正を書きます。結果には各設定に対する最小権限の説明が
表示されます。トラックページはカテゴリ別・スキル別のクラウド弱点統計を表示します。

焦点: 最小権限、公開露出、ログ記録、暗号化、秘密情報の取り扱い。

セーフモード: 合成設定ファイルのみ。

## トラック 4: SOC ログ調査

ワークスペース: `/tracks/soc` には 10 個のログ調査チャレンジ（`src/data/tracks/soc.ts`）があり、認証ログ、Web
アクセスログ、DNS ログ、エンドポイントアラート、ファイアウォールログを各 2 問扱います。各チャレンジは CEH
モジュールと `soc-*` スキルタグを持ちます。学習者は指標行を選び、タイムスタンプ付きの行からタイムラインを作成し
（各イベントに観察が必要）、活動を分類し、指標・影響を受ける資産・次のアクションを書きます。結果は検知ロジックと
封じ込め案、モデルのタイムラインを表示します。誤答はレビューキューに入ります。

焦点: タイムライン、インジケーター、影響を受けた資産、封じ込めのアイデア。

セーフモード: 合成ログのみ。

## トラック 5: インシデントレスポンス報告

ワークスペース: `/tracks/ir` は架空のインシデント（NeonCorp の RecordVault アプリでの MFA なしアカウント乗っ取りと
一括エクスポート）を 4 つの合成アーティファクトから再構成します。タイムラインのイベントは時刻、ソース、観察、
確信度、関連証拠を持ち、学習者はアーティファクト行、手動イベント、関連チャレンジ（SOC-01、SOC-02）の SOC
トラックのタイムラインを取り込めます。IR レポートはインシデント概要、影響、封じ込め、根絶、復旧、教訓を扱い、
品質チェックリストと証拠不足の警告で下書きを支援し、モデルのタイムライン/レポートと比較し、Markdown で
エクスポートできます。

焦点: タイムライン、影響、封じ込め、根絶、回復、教訓。

セーフモード: 架空のインシデントシナリオのみ。

## トラック 6: 脅威モデリングと修正

ワークスペース: `/tracks/threat-model` には 5 つの架空シナリオ（`src/data/tracks/threatModel.ts`）があり、
データフロー図、コンポーネント、フロー、信頼境界、資産を含みます。学習者は資産の機密度を評価し、各信頼境界で
強制すべきことを書き、要素やフローごとに設計上の緩和策と優先度を伴う STRIDE 脅威を記録します（必須の STRIDE
カテゴリを網羅する必要あり）。脅威は CEH の概念（例: Session hijacking (M11)）に結び付きます。成果物は
ステータス管理付きの優先度順の修正バックログで、Markdown でエクスポートでき、所見と修正計画として Report
Builder に送れます。下書き後にモデルの脅威と比較できます。

焦点: 資産、信頼境界、脅威、緩和策。

セーフモード: 架空のアーキテクチャ図のみ。

## ラボスコアリングルブリック

セーフラボは、以下のコンポーネントで実践作業をスコアリングします：

- フラグ / 診断
- 証拠
- 説明
- 修正
- 安全性の確認

各ラボはチャレンジタイプを定義し、ルブリックコンポーネントをその目的にマッピングします。ヒントと欠落したスコープの確認はペナルティを適用します。設定により、合格スコア、ヒントペナルティ、およびスコープ警告ペナルティを調整できますが、ラボの内容は変更されません。

フラグコンポーネントは、受け入れられた `FLAG{UPPER_SNAKE_CASE}` の提出によってのみ獲得されます。試行とユニークなヒントの公開はローカルに保持され、分析に供給されます。受け入れられたフラグはさらなる提出をロックし、説明/修正/報告のプロンプトを解除し、モデルの発見を有効にします。ガイディングクエスチョンのヒントとフラグチャレンジのヒントは、設定されたヒントペナルティに寄与します。

## トラックチャレンジエンジン

AppSec・クラウド・SOC のチャレンジは 1 つのエンジン（`src/lib/trackChallenges.ts`）を共有します: 関連する
アーティファクト行を選び、問題を分類し、成果物を書きます。採点は行 40%・分類 30%・記述 30% で、すべての
正解行を選び（余分な文脈行は 1 行まで許容）分類が一致すると正解です。各チャレンジはモジュール 0 の復習問題
（`TC-<id>`）に変換され、提出は `practical` の試行として記録され、誤答はレビューキューに入ります。トラック
ページはカテゴリ別・スキル別の弱点統計を表示します。コンテンツはテストでスキーマ、トラック固有の項目、
ラボ安全監査ルール（コードとログ行はアーティファクトモード）を検証します。

## データセット分析チャレンジ

セーフラボには、必須のアーティファクト種別ごとにデータセット分析チャレンジがあります: PCAP /
パケットサマリー（`net-cleartext`）、Web アクセスログ（`web-log-forced-browsing`）、認証ログ
（`soc-bruteforce`）、クラウド設定（`cloud-iam`）、ファイアウォールルール（`fw-rule-shadowing`）、
メールヘッダー（`phish-headers`）。各分析チャレンジのルーブリックは、受理されたフラグ（回答）、証拠、
修正を要求し、フラグ受理後に検知 + 予防の解説が表示されます。

ラボ詳細では合成アーティファクトを行番号付きビューアで表示します。学習者は所見を裏付ける行を選択し、
ログ抜粋として Evidence Vault に保存するか、**Send to report** でラボレポートに引用できます
（レポートが無い場合はモデル所見から作成）。引用は Markdown エクスポートに含まれます。

## Web アプリセキュリティコンセプトラボ

4 つの静的 Web コンセプトラボが、アクセス制御の不備（`web-idor`）、入力検証（`web-input-validation`）、
セッション管理（`web-session-rotation`）、セキュリティヘッダー（`web-security-headers`）を扱います。
いずれも架空のトイアプリのリクエスト/レスポンスまたはヘッダーのキャプチャを使い、スコープ契約内に
危険なターゲットの警告を表示し、学習者が所見・影響・修正を書く Finding Worksheet を備えます。
完成したワークシートは重大度を選んでラボレポートの所見として追加できます。ペイロード集や実サイトの
検査手順は含みません。

## 脆弱性トリアージ

トリアージボード（`/triage`）は所見を優先度付きの作業に変えます。各トリアージ所見はタイトル、影響を受ける
資産、証拠、影響、発生可能性、重大度、修正、ステータスを記録します。重大度は 4×4 の影響度 × 発生可能性
ルーブリック（スコア 1-16 → info/low/medium/high/critical）と任意の手動上書きを組み合わせ、ルーブリック
から大きく外れる場合は警告します。ステータスは `open → confirmed | false-positive`、
`confirmed → accepted-risk | fixed`（再オープン経路あり）で、false positive・accepted risk・fixed には
理由メモが必須です。修正優先度（P1-P4）は実効重大度とステータスから導出します。ラボ詳細からモデル所見を
オープンなトリアージ項目として取り込め、有効な所見は既存または新規のレポートに追加できます。再追加は同じ
レポート所見を更新し、Markdown エクスポートには資産・ステータス・発生可能性が含まれます。

## レポートビルダー

レポートは 6 つのセクション（エグゼクティブサマリー、スコープ、方法論、所見、修正計画、付録）を持ちます。
セーフラボからレポートを作成すると、スコープ、サマリー、方法論、モデル所見、合成アーティファクトを列挙した
付録が入ります。**Draft from findings** は重大度の内訳と最上位の所見からエグゼクティブサマリーを作成し、
**Generate from findings** は重大度順の修正ロードマップを作成し、**Sort by severity** は所見を並べ替えます。
品質チェックリストは全項目（エグゼクティブサマリー、合成スコープ、方法論、所見、所見の必須項目、証拠の引用、
修正計画、重大度順、付録、安全性）を合否付きで表示します。安全警告は常に表示され、検出された公開 IP、
実在のメールホスト、訓練用でない URL、資格情報、秘密鍵、トークンをフィールドごとに列挙します。

## CEH Practical 形式シミュレーター

実技シミュレーター（`/practical`）はハンズオン実技試験の形式だけを模倣します: 時間制限付きの 20 問
（Full: 6 時間、Sprint: 2 時間）。各セッションはシードに基づき、`practical` タグのシード質問
（`group-p.json`）からデータセット分析 8、設定レビュー 5、コンセプトラボ 4、レポートプロンプト 3 を CEH
モジュールを分散させて選びます。答えはすべてチャレンジ本文の合成アーティファクトから導き、レポート
プロンプトはモデル解答と比較して自己採点します。自信のないチャレンジには印を付けられます。終了時の
準備度レポートは種類・CEH モジュール・スキル別に集計し、次のアクションを示し、Markdown で出力できます。
各チャレンジは `practical` の試行として記録され、誤答は失敗したレビューと同様に、正解でも自信なしの
ものは短い間隔でスケジュールされ、どちらもレビューキューに表示されます。

## ポートフォリオエビデンスエクスポーター

ポートフォリオ画面（`/portfolio`）は、模擬試験の統計、実技シミュレーターの結果、CEH+ トラックの進捗、選択した
ラボレポート、サニタイズ済みのトリアージ所見、振り返りメモから Markdown ポートフォリオを生成します。既定は
公開安全モードで、証拠メモ・提出した回答・フラグは除外され、公開 IP、実在のメール、訓練用でない URL、実在 TLD の
ホスト名、資格情報の値は `[ip-removed]` や `[redacted]` のようなプレースホルダーに置き換えられます。機密
プレースホルダーチェックは最終 Markdown を走査し（機密値が残る間はエクスポート不可）、`TODO` や `<your name>`
のような未完成のテンプレートも警告します。エクスポート/コピーの前にプライバシーチェックリストをすべて確認する
必要があります。

## セキュリティ面接準備トラッカー

面接トラッカー（`/interview`）は学習と実践を面接で話すストーリーに対応付けます。各 CEH ドメインと CEH+
トラックについて、問題回答による概念の正答率、解いたセーフラボ、関連ラボレポート、解いたトラックチャレンジを
根拠として示し、strong / developing / gap のステータスを付けます。gap には正直な弱点の説明と、弱いモジュールや
未解決のラボ・チャレンジに基づく次の計画が付きます。ストーリーは STAR（状況・課題・行動・結果）または簡潔形式で、
根拠を引用し、話す時間の目安付きの英語回答メモ（1〜2 分が目標）を含みます。保存したストーリーはポートフォリオ
エクスポーターの Interview Stories セクションに反映されます。

## ラボレジストリの安全性

すべてのラボは `kind`: `local`, `dataset`, `simulated`, または `writeup` を宣言します。ラボの詳細は証拠の前にスコープ契約を表示し、学習者は開始前に合成の読み取り専用境界を確認する必要があります。レジストリバリデーターは、欠落したスコープ、無効な種類、公開IPアドレス、実際のメールドメイン、ライブドメイン、および資格情報のような割り当てを拒否します。CIはまた、`npm run validate:safety` を実行し、安全でないラボメタデータが公開されないようにします。レジストリの検証には、プロンプト、ローカル資産メタデータ、ユニークな期待されるフラグ、少なくとも1つのスコープ付きヒント、説明、修正、および各ラボの報告プロンプトが必要です。 分析チャレンジは、有効な `analysis.type` と検知・予防の説明も宣言する必要があります。
